Run DBOS workflows on your own infrastructure.

Relay is an open-source control plane for DBOS Transact. Use the Conductor protocol on supported SDKs, or connect directly to the application system database on post-split SDKs. No vendor key, and no connector in Direct mode.

Two ways to connect.

Pick the mode that matches your SDK. Both use the same control plane, dashboard, and API. Recovery follows each mode's liveness signal.

Attached

Conductor protocol

For Go 1.6.0 and earlier, Python 3.2.0 and earlier, TypeScript 5.2.11 and earlier, and Java. Point the application's Conductor URL and key at Relay. The connector stays in the app.

export DBOS__CLOUD=true
export DBOS__CONDUCTOR_APP_NAME=checkout
export DBOS__CONDUCTOR_URL=ws://relay:8090
export DBOS__CONDUCTOR_KEY=...

Direct

No connector

For Go 1.7 and 1.8, Python 3.3 and 3.4, and TypeScript 5.3 and 5.4. Relay reads and controls the application through its system database using DBOS's MIT Go client. Schema 123 through 125.

data_plane:
  checkout:
    connection_string_from:
      env: CHECKOUT_DB_URL
    integration: direct
    mode: read-write

Java 1.2.0 is schema 114 and uses Attached. Direct mode needs a database connection and, for automatic recovery, a liveness signal from relay probe. Read the Direct mode guide.

The control plane, not another runtime.

Your application keeps its own database and its own execution model. Relay adds the fleet view, recovery, schedules, queues, alerts, and the API around it.

Recovery
In Attached mode, a dead executor's work is handed to a healthy peer. In Direct mode, Relay re-enqueues it through the system database after relay probe or an operator reports the executor gone.
Fleet view
Applications, executors, versions, queues, and schedules in one console.
Workflow DAG
Root steps and child workflows with timings, outcomes, inputs, and outputs.
Schedules and queues
Cron schedules, queue limits, partitions, and manual triggers.
Declarative config
relay apply and relay diff from a YAML manifest, ready for GitOps.
One binary
Embedded SQLite for a laptop. PostgreSQL for a clustered deployment. OpenMetrics at /v1/metrics.

Start in a minute.

Run Relay with embedded SQLite, then choose a connection mode. Nothing else is required for the first workflow.

1. Run Relay

Download the binary and start the embedded control plane.

curl -fsSL https://github.com/abn/dbos-relay/releases/latest/download/relay-linux-amd64 -o relay
chmod +x relay
./relay serve --embedded

Open http://localhost:8090. The console and the API are on the same port.

2. Connect an application

Attached

Set the standard Conductor environment variables on the app, then start it.

export DBOS__CLOUD=true
export DBOS__CONDUCTOR_APP_NAME=checkout
export DBOS__CONDUCTOR_URL=ws://127.0.0.1:8090
export DBOS__CONDUCTOR_KEY=...

Direct

Add a data_plane block to relay.yaml, apply it, then run the probe beside the app.

relay apply -f relay.yaml

export DBOS_APP_NAME=checkout
export DBOS__VMID=checkout-0
export DBOS__APPVERSION=v1
export RELAY_INTERNAL_SECRET=...
relay probe --relay-url http://127.0.0.1:8090 \
  --org production --app "$DBOS_APP_NAME"

No application code changes in either mode. Full quickstart.

Relay and Conductor.

Relay is not a managed service. It is the control plane you run, on the infrastructure and database you already have.
